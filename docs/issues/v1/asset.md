### AST-01 리그가 시작되면 모든 참여자에게 총 1억 원 상당의 주식과 현금이 배분된다
- Jira: ND-11
- 정책: [asset.md#초기-자산-배분](../../policies/v1/domain/asset.md#초기-자산-배분)
- 선행: LEA-09, MKT-04
- 내용: `LeagueStarted` 구독, 배분 완료 시 거래 개시 가능 상태로 전환
- 완료 조건
  - [X] 종목당 5,000주: 상장자 2,500주, 나머지 2,500주를 다른 참여자에게 균등 배분, 잔여분은 상장자
  - [X] 초기 현금 = 1억 원 - 배분받은 전체 주식 수 × 10,000원
  - [X] 참여자 3~10명 전 구간 단위 테스트 (잔여 주식 발생 케이스 포함)
  - [X] 배분은 원자적으로 처리 (일부만 배분된 상태로 거래 개시 불가)
  - [X] `LeagueStarted` 구독 구현 (이벤트 발행은 LEA-09)
  - [X] 초기 배분 주식의 매입 금액 = 배분 수량 × 10,000원

### AST-02 참여자는 자신의 현금, 보유 주식, 예약 자산, 총자산을 조회할 수 있다
- Jira: ND-10
- 정책: [asset.md#자산-조회](../../policies/v1/domain/asset.md#자산-조회), [#총자산-집계](../../policies/v1/domain/asset.md#총자산-집계)
- 선행: AST-01, MKT-08, AST-08
- 완료 조건
  - [X] 보유 중인 현금이 조회 돼야 한다.
  - [X] 보유 주식에 대한 평가금액이 조회 돼야 한다.
  - [X] 현금과 보유 주식의 평가금액을 합쳐 총 자산이 조회돼야 한다.
  - [X] 보유 중인 주식의 경우 종목 이름, 보유 수량, 내 종목 여부, 평가 금액, 평가 손익, 수익률이 보여야 한다
    - 평가 손익 = 평가 금액 - 보유 수량 × 시초가 10,000원 (매입 금액·평단가 기준은 미정)
    - 수익률(%) = 평가 손익 ÷ (보유 수량 × 시초가) × 100, 소수점 첫째 자리까지 반올림, 음수는 절댓값 기준 (-12.35% → -12.4%)
  - [X] 총 자산에 대한 평가 손익도 보여야 한다. (총자산 - 1억 원, 매도로 현금이 된 손익 포함)
  - [X] 총자산 수익률도 보여야 한다. (총자산 평가 손익 ÷ 1억 원 × 100, 소수점 첫째 자리까지 반올림, 음수는 절댓값 기준)
  - [ ] 본인 자산은 실시간 조회가 가능해야 한다. (변동될 경우 화면에서 변경) (웹소켓)
    - 내 주문 체결 시 매수자·매도자에게 즉시 발행 (커밋 이후), 현재가 변동은 주기 발행으로 전원 갱신
    - 두 경로 모두 DB 상태로 매번 다시 계산 (누적 방식 금지), 메시지 순서 역전 대비 계산 시각 포함
  - [X] 로그인한 회원 본인(해당 리그의 플레이어)의 자산만 조회할 수 있어야 한다.
- 설계: [docs/design/asset-realtime.md](../../design/asset-realtime.md) (조회 경로, 발행 시점, 주의 사항)
- 참고: 대기 중인 주문(매수·매도 모두)은 order의 별도 API로 조회한다 ([ORD-08](order.md#ord-08-참여자는-자신의-미체결-주문과-체결-내역을-조회할-수-있다)). 화면은 두 API를 함께 호출한다

### AST-03 참여자는 사용 가능한 현금 범위에서만 매수 주문을 넣을 수 있다
- Jira: ND-30
- 정책: [asset.md#주문-가능-자산-및-정산](../../policies/v1/domain/asset.md#주문-가능-자산-및-정산)
- 선행: AST-01
- 완료 조건
  - [ ] 주문 가능 현금 = 현금 - 예약 현금, 부족 시 거절
  - [ ] 지정가: 지정 가격 × 수량, 시장가: 보호 조건 내 최고 체결 가능 가격 × 수량

### AST-04 참여자는 매도 가능한 수량 범위에서만 매도할 수 있고, 자사주는 1,000주를 남겨야 한다
- Jira: ND-31
- 정책: [asset.md#주문-가능-자산-및-정산](../../policies/v1/domain/asset.md#주문-가능-자산-및-정산), [#자사주-최소-유지분](../../policies/v1/domain/asset.md#자사주-최소-유지분)
- 선행: AST-01
- 완료 조건
  - [ ] 매도 가능 수량 = 보유 - 예약, 부족 시 거절
  - [ ] 자사주: max(0, 보유 - 기존 매도 예약 - 1,000주)
  - [ ] 체결 시에도 최소 유지분 보호

### AST-05 체결이 발생하면 매수자와 매도자의 현금과 주식이 즉시 정산된다
- Jira: ND-32
- 정책: [asset.md#주문-가능-자산-및-정산](../../policies/v1/domain/asset.md#주문-가능-자산-및-정산)
- 선행: AST-03, AST-04
- 완료 조건
  - [ ] 매수: 현금 감소·주식 증가, 매도: 주식 감소·현금 증가 (실제 체결가·수량 기준)
  - [ ] 체결가가 예약 기준가보다 낮으면 차액 예약 해제
  - [ ] 매수자·매도자 정산을 한 트랜잭션에서 처리
  - [ ] 체결 시 매입 금액 갱신 (이동평균법): 매수 시 `+ 체결가 × 체결 수량`, 매도 시 `기존 매입 금액 × 매도 후 보유 수량 ÷ 매도 전 보유 수량` (원 미만 절사), 보유 수량이 0이 되면 0

### AST-06 주문이 취소되거나 만료되면 묶여 있던 현금과 주식이 해제된다

### AST-07 탈퇴한 회원의 현금은 폐기되고 보유 주식은 더 이상 거래되지 않는다
- Jira: ND-59
- 정책: [member.md#회원-탈퇴](../../policies/v1/domain/member.md#회원-탈퇴)
- 선행: MBR-06, ORD-11
- 완료 조건

  - [ ] 보유 주식은 수량 유지, 이후 거래 불가 (발행주식 총수에 포함)

### AST-08 시스템은 참여자별 총자산을 집계할 수 있다
- Jira: ND-62
- 정책: [asset.md#총자산-집계](../../policies/v1/domain/asset.md#총자산-집계)
- 선행: AST-01
- 내용: 리그가 호출 (진행 중 순위, 리그 결과). 평가 가격은 호출하는 쪽이 종목별로 넘긴다
- 완료 조건
  - [ ] 총자산 = 현금 + Σ(보유 수량 × 평가 가격), 자사주 포함
  - [ ] 평가 가격은 호출자가 지정 (진행 중: 현재가, 종료 시: 종료 평가 가격)
  - [ ] 원 미만 절사
  - [ ] 참여자별 현금, 종목별 보유 수량·평가액, 총자산을 함께 반환
