### CNT-02 참여자는 종목별 공시 목록과 상세 내용을 볼 수 있다
- Jira: ND-15
- 선행: CNT-01
- 완료 조건
  - [x] 종목별 공시 목록, 상세 (제목, 본문, 이미지, 작성 정보, 반응 수)
  - [x] 삭제된 공시 원문은 목록·상세에서 조회 불가
  - [x] 상세에 연결된 뉴스 (공시 삭제와 관계없이 이미 발행된 뉴스는 조회 가능. 삭제된 공시의 뉴스 조회는 CNT-08에서 처리)
- 결정: 종목별 목록을 제공하고, 리그 전체에서 공시·뉴스를 함께 보는 통합 피드는 CNT-11에서 제공한다
- 결정: 목록은 `GET /api/leagues/{leagueId}/stocks/{stockId}/disclosures?cursor=&size=` 작성 일시 최신순(같으면 ID 내림차순) 커서 페이징 (기본 20, 최대 50). 커서는 통합 피드(CNT-11)와 같은 불투명 문자열이고 형식이 틀리거나 다른 종류의 커서면 `002`로 거절. 상세는 `GET .../disclosures/{disclosureId}`
- 결정: 목록·상세 모두 전체 이미지 서명 URL을 첨부 순서대로 준다 (공시 카드에 첨부 사진을 모두 보여 줌). 서명 URL 발급마다 IAM 호출이 있어 목록 한 페이지에서 최대 공시 수 × 4번 호출된다
- 결정: 리그에 입장한 플레이어만 조회하며, 종료된 리그의 공시도 조회할 수 있다
- 결정: 작성 정보는 거래일·작성 일시·작성자 플레이어 ID·내 공시 여부. 작성자 이름은 종목 조회의 상장자 이름을 쓴다 (작성자 = 상장자)
- 결정: 상세에만 연결된 뉴스를 생성 상태(`PENDING`·`PUBLISHED`·`SKIPPED`·`FAILED`)와 함께 준다. 제목·본문·호재/악재는 `PUBLISHED`일 때만 있다. 목록에는 넣지 않는다
- 결정: 공시와 뉴스의 목록·상세는 같은 구조로 맞춘다. 목록·상세 모두 댓글 수(`commentCount`)를 주고, 목록은 미리보기 댓글 1개(`previewComment`: 가장 먼저 등록된 댓글, 없으면 `null`)를, 상세는 그 대신 댓글 전체(`comments`: 오래된 순 배열, 페이징 없음)를 준다. 커서 페이징은 공시 목록·뉴스 목록에만 둔다. 상세에는 연관 콘텐츠(공시 상세는 `news`)가 더해진다. 목록의 댓글 미리보기는 페이지 단위로 한 번에 조회하고, 목록의 `nextCursor` 규칙은 공시·뉴스가 같다

## 뉴스

### CNT-05 공시가 게시되면 AI가 공시 내용을 바탕으로 뉴스 1개를 생성한다
- Jira: ND-19
- 정책: [contents.md#뉴스---공시-기반-ai-뉴스](../../policies/v1/domain/contents.md#뉴스---공시-기반-ai-뉴스)
- 선행: CNT-01, GLB-06
- 내용: `DisclosurePublished` 비동기 구독
- 완료 조건
  - [x] 공시 1건당 뉴스 1개 (공시와 일대일, 종목과 다대일)
  - [x] 공시 원문의 사실 기준 작성, 말이 되는 문장이 없으면 미생성
  - [x] 제목 최대 30자, 본문 최대 100자, 이미지 없음, 삭제 불가
  - [x] 호재/악재 판정 함께 저장
  - [x] 생성 실패해도 공시 원문 유지
- 결정: "미생성"은 실패가 아닌 정상 결과로 보고 재시도하지 않는다 (`news.status = SKIPPED`). AI가 판단한 미생성 사유는 `disclosure.ai_skip_reason`(비공개)에 저장한다
- 결정: 공시 저장 커밋 후 비동기(`@Async`, `global/config/AsyncConfig`)로 생성한다. 공시를 저장하는 트랜잭션에서 `news` 행을 생성 중(`PENDING`)으로 함께 저장해, 공시가 있으면 뉴스 행도 반드시 있게 한다. `disclosure_id` 유니크 제약으로 공시당 1개를 보장한다. 커밋 후 비동기로 `PENDING` 뉴스의 내용을 채우고 결과에 따라 `PUBLISHED`·`SKIPPED`·`FAILED`로 바꾼다
- 결정: AI가 함께 만든 공시 요약은 `disclosure.ai_summary`(비공개)에 저장하고, 같은 종목의 다음 뉴스 생성 때 과거 맥락으로 넘긴다. 삭제된 공시의 요약도 포함하고 요약이 없는 공시(미생성·실패)는 제외한다 (오래된 순)
- 결정: 공시 이미지는 서명 URL로 AI에 넘긴다 (로컬 파일 저장소 URL은 외부에서 내려받을 수 없어 이미지가 있는 공시는 로컬에서 실패한다)

### CNT-07 공시 작성자는 자동 재시도까지 실패한 AI 뉴스를 직접 다시 생성할 수 있다
- Jira: ND-102
- 정책: [contents.md#뉴스---공시-기반-ai-뉴스](../../policies/v1/domain/contents.md#뉴스---공시-기반-ai-뉴스)
- 선행: CNT-06
- 완료 조건
  - [x] 공시 작성자만, 자동 재시도 모두 실패한 경우만
  - [x] 공시가 삭제되지 않았고 리그가 진행 중일 때만
  - [x] 수동 요청에도 자동 재시도 최대 2회 적용
- 결정: Jira ND-102 설명("종목에 관계없이 참여자 누구나")과 달리 정책서 기준(공시 작성자만)을 따른다
- 결정: 요청은 `POST /api/leagues/{leagueId}/stocks/{stockId}/disclosures/{disclosureId}/news/regenerate`. `FAILED` 뉴스를 `PENDING`으로 되돌리고 커밋 후 비동기로 다시 생성한다 (CNT-05와 같은 흐름). 응답은 뉴스 ID와 `PENDING` 상태. `FAILED`가 아니면(`PENDING`·`PUBLISHED`·`SKIPPED`) 거절
- 결정: 재생성 요청은 뉴스당 1분에 1번만 가능하다. 마지막 요청 시각을 `news.regeneration_requested_at`에 기록하고(`Clock` 기준), 1분이 지나지 않았으면 거절한다
- TODO: PENDING에 멈춘 뉴스 복구. 공시 저장 커밋 직후 서버가 종료되면 비동기 생성이 실행되지 않아 뉴스가 `PENDING`으로 남는다. 오래된 `PENDING`을 다시 생성하는 방법(배치 또는 수동 재시도 허용)을 정하고, 같은 뉴스를 두 번 생성하지 않도록 처리 중 표시(낙관적 락 등)를 함께 둔다

## 댓글

### CNT-09 참여자는 공시와 뉴스에 댓글을 작성하고 조회할 수 있다
- Jira: ND-101
- 정책: [contents.md#댓글-공통](../../policies/v1/domain/contents.md#댓글-공통)
- 선행: CNT-01, CNT-05
- 완료 조건
  - [x] 공시·뉴스 공통 적용, 최대 100자, 이미지 불가, 대댓글 불가
  - [x] 작성자 계정 이름 표시
- 결정: 뉴스 댓글 작성은 `POST /api/leagues/{leagueId}/stocks/{stockId}/news/{newsId}/comments` (`{"content":"..."}`), 목록은 `GET` 같은 경로로 오래된 순(ID 오름차순) 전체를 배열로 준다. 댓글이 많지 않아 페이징하지 않는다 (상세의 `comments`와 같은 목록). 종목과 관계없이 리그 참여자면 작성할 수 있다
- 결정: 작성은 진행 중인 리그에서만 가능하고, 조회는 종료된 리그에서도 가능하다. 발행된(`PUBLISHED`) 뉴스에만 작성할 수 있다
- 결정: 목록 항목은 댓글 ID, 내용, 작성자 플레이어 ID, 작성자 이름, 내 댓글 여부, 작성 일시
- 결정: 공시 댓글은 뉴스 댓글과 테이블을 나눠 `disclosure_comment`에 저장하고(공통 필드·규칙은 `Comment`), 작성·조회·삭제는 뉴스 댓글과 같은 절차(`CommentService`)를 따른다. 경로는 `.../disclosures/{disclosureId}/comments` (작성 `POST`, 목록 `GET`, 삭제 `POST .../{commentId}/delete`). 삭제된 공시의 댓글은 작성·조회·삭제 모두 공시 없음(`607`)으로 거절한다

### CNT-11 참여자는 리그의 공시와 뉴스를 한 목록에서 최신순으로 볼 수 있다
- Jira: ND-106
- 정책: [contents.md#공시](../../policies/v1/domain/contents.md#공시), [contents.md#뉴스---공시-기반-ai-뉴스](../../policies/v1/domain/contents.md#뉴스---공시-기반-ai-뉴스)
- 선행: CNT-02, CNT-08
- 완료 조건
  - [x] 리그의 공시와 발행된 뉴스를 한 목록에 등록 일시 최신순으로 제공
  - [x] 종목·종류(공시·뉴스)로 걸러 조회
  - [x] 항목은 종목별 공시 목록(CNT-02)·뉴스 목록(CNT-08)의 항목과 같고, 보이는 범위(삭제된 공시 제외, 발행된 뉴스만, 공시가 삭제돼도 발행된 뉴스는 보임)도 같다
- 결정: `GET /api/leagues/{leagueId}/feed?stockId=&type=&cursor=&size=`. `stockId`·`type`(`DISCLOSURE`·`NEWS`)은 선택이고 생략하면 리그 전체·둘 다. 커서 페이징 (기본 5, 최대 50)
- 결정: 등록 일시는 공시는 작성 일시(`created_at`), 뉴스는 발행 일시(`published_at`)다. 같으면 공시 먼저, 같은 종류면 ID 내림차순. 커서는 (등록 일시, 종류, ID)를 담은 불투명 문자열이고 형식이 틀리면 `002`로 거절
- 결정: 항목은 종목별 공시 목록·뉴스 목록의 항목과 같은 모양이고 `type`(`DISCLOSURE`·`NEWS`)으로 구분한다. 두 종목별 목록 항목에도 `type`을 넣는다. 리그에 입장한 플레이어만 조회하며, 종료된 리그도 조회할 수 있다
