- 완료 조건

- 메모: 리그 이름이나 방장 종목이 규칙에 맞지 않으면 리그 생성도 롤백

- Jira: ND-80, ND-55
- 정책: [league.md#대기실](../../policies/v1/domain/league.md#대기실)
- 선행: LEA-05
- 완료 조건

- 결정: 퇴장한 참여자의 종목은 삭제한다. 나간 플레이어 행도 삭제해 초대 코드로 다시 입장할 수 있다. 삭제된 대기실은 `DELETED` 상태로 남기고 초대 코드를 폐기한다.
- 비고: 퇴장은 구현됨. 종목 삭제는 market에 종목 삭제 서비스가 생기면 `LeagueLeaveUseCase`의 TODO에서 호출한다.

### LEA-07 방장은 리그 시작 전에 리그 이름 수정, 리그 삭제, 참여자 추방을 할 수 있다
- Jira: ND-54
- 정책: [league.md#대기실](../../policies/v1/domain/league.md#대기실)
- 선행: LEA-05
- 완료 조건
  - [X] 리그 이름 수정, 리그 삭제, 참여자 추방은 방장만, 대기실 상태에서만 가능
- 결정: 방장은 참여자뿐 아니라 대기자(상장 전)도 추방할 수 있다. 방장 자신은 추방할 수 없다 (방장은 대기실 나가기로 위임). 추방된 플레이어는 나가기와 같이 행을 지우므로 초대 코드로 다시 입장할 수 있다. 삭제된 리그는 `DELETED` 상태로 남기고 초대 코드를 폐기한다.
- 비고: 추방된 참여자의 종목 삭제는 LEA-06과 같이 market에 종목 삭제 서비스가 생기면 `LeagueHostUseCase`의 TODO에서 호출한다.

### LEA-10 참여자는 리그 종료 시각과 현재 몇 거래일차인지 알 수 있다
- Jira: ND-58
- 정책: [league.md#리그-시작-및-운영](../../policies/v1/domain/league.md#리그-시작-및-운영), [market.md#시장](../../policies/v1/domain/market.md#시장)
- 선행: GLB-03
- 완료 조건
  - [X] 종료 시각 = 시작 KST 날짜 + 7일, 09:00 KST
  - [X] 00:00~09:00 시작 시 당일 09:00까지는 거래일 계산에서 제외, 사용자에게는 1일차로 표시
  - [X] 특정 시각의 거래일 번호 계산 (09:00 이상 ~ 다음 날 09:00 미만)
  - [X] 경계 시각(08:59:59, 09:00:00) 테스트
- 결정: 새벽(00:00~09:00) 시작 구간은 별도 거래일이 아니라 1일차에 포함한다. 따라서 거래일은 언제 시작하든 1~7일차다 (정책서 "8거래일" → "7거래일", ERD `trading_day.일차` 1~8 → 1~7). 종료 시각은 리그 시작 시 `league.ends_at`에 확정하고, 1~7일차 `trading_day` 행도 시작 시 한 번에 만든다.
- 비고: 계산은 `TradingSchedule`(`League.tradingSchedule()`)이 맡는다. 현재 거래일차와 종료 시각은 리그 상세 조회(`GET /api/leagues/{leagueId}/detail`)의 `tradingDay`로 내려주며 대기실이면 `null`이다. 리그 시작 응답에도 `endsAt`을 포함한다. 종료 시각 이후 접근 차단은 LEA-12에서 처리하며, 그 전까지는 7일차로 응답한다.

### LEA-13 리그가 종료되면 참여자의 최종 총자산과 순위가 산정된다
- Jira: ND-86

- 선행: LEA-12, MKT-07, AST-05
- 완료 조건

  - [ ] 자사주 포함, 총자산 동일 시 공동 순위
  - [ ] 공동 순위 이후의 순위는 해당 순위에 동점자 수를 더해 산정 (예: 공동 1위 2명이면 다음은 3위)
  - [ ] 최종 손익 = 최종 총자산 - 1억 원, 최종 수익률 = 최종 손익 ÷ 1억 원 × 100
  - [ ] 종료 전 탈퇴자는 순위·결과에서 제외
  - [ ] 결과 스냅샷 저장 (참여자별 현금, 종목별 보유 수량·평가액, 총자산)
- 결정 필요: 최종 수익률 반올림 규칙 (자산 조회와 같이 소수점 둘째 자리에서 반올림, 음수는 절댓값 기준인지)
