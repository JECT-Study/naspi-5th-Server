# [리그] league

> 정책: [docs/policies/v1/league.md](../../policies/v1/domain/league.md)

## 대기실

### LEA-01 회원은 리그 이름을 정하고 자신의 종목을 상장해 리그를 만들 수 있다
- Jira: ND-50
- 정책: [league.md#리그-생성-및-초대](../../policies/v1/domain/league.md#리그-생성-및-초대)
- 선행: MBR-01
- 내용: 리그 이름과 방장의 종목(이름·소개)을 한 번에 받아 리그 생성. `LeagueCreationUseCase`가 리그·방장을 만들고 market에 방장 종목 상장(MKT-01)을 요청해 같은 트랜잭션에서 생성 완료. 생성 시 대기실과 초대 코드 발급
- 완료 조건
  - [ ] 리그 이름 최대 12자, 모든 문자 허용, 중복 허용
  - [ ] 리그당 공통 초대 코드 1개 생성 (영문 대문자·숫자 7자리, 대기실 리그 사이 중복 불가)
  - [ ] 동시 참여 리그 수 제한 검증 (LEA-02)
- 메모: 리그 이름이나 방장 종목이 규칙에 맞지 않으면 리그 생성도 롤백

### LEA-02 회원은 대기실과 진행 중인 리그를 합쳐 최대 5개까지만 참여할 수 있다
- Jira: ND-51
- 정책: [league.md#리그-생성-및-초대](../../policies/v1/domain/league.md#리그-생성-및-초대)
- 선행: LEA-01, LEA-03
- 내용: 리그 생성(LEA-01)과 초대 코드 입장(LEA-03) 시 회원이 참여 중인 리그 수를 확인해 5개 이상이면 거절
- 완료 조건
  - [X] 대기실 + 진행 중 리그 합계 최대 5개, 종료된 리그는 제외
  - [X] 리그 생성 시와 대기실 입장 시 모두 검증
  - [X] 최대 참여 개수 초과 시 리그 생성·입장 불가 (오류 코드 205)
- 메모: 같은 회원이 동시에 여러 리그를 생성·입장하는 경우는 막지 않는다 (회원 단위 잠금 필요)

### LEA-03 회원은 초대 코드로 리그 대기실에 입장할 수 있다
- Jira: ND-50
- 정책: [league.md#대기실](../../policies/v1/domain/league.md#대기실)
- 선행: LEA-01
- 완료 조건
  - [ ] 입장 시 대기자 상태
  - [ ] 만료된 코드, 시작된 리그, 참여 제한 초과 시 거절
  - [ ] 초대 코드는 대소문자 구분 없이 입력

### LEA-04 대기실의 사용자는 방장·참여자·대기자 목록과 리그 시작 가능 여부를 볼 수 있다
- Jira: ND-53
- 선행: LEA-03
- 완료 조건
  - [ ] 방장, 참여자, 대기자 목록과 각 참여자의 종목 정보
  - [ ] 리그 시작 가능 여부 (참여자 3명 이상, 대기자 0명)

### LEA-05 대기자는 종목 상장을 마치면 참여자가 된다
- Jira: ND-53
- 정책: [league.md#대기실](../../policies/v1/domain/league.md#대기실)
- 선행: LEA-03, MKT-01
- 완료 조건
  - [ ] 대기실에 진입한 사용자는 상장 완료 여부에 따라 대기자 또는 참여자로 구분 (방장도 상장을 완료하면 참여자)
  - [ ] 상장 완료 시 대기자 → 참여자 전환, 상장 완료 여부·상장일시 기록 (방장 위임 기준)
  - [ ] 참여자 + 대기자 10명이면 입장 불가 (동시 입장 시에도 10명 초과 불가)

### LEA-06 대기실의 사용자는 리그 시작 전에 대기실을 나갈 수 있고, 방장이 나가면 다음 참여자에게 방장이 위임된다
- Jira: ND-80, ND-55
- 정책: [league.md#대기실](../../policies/v1/domain/league.md#대기실)
- 선행: LEA-05
- 완료 조건
  - [ ] 참여자·대기자 퇴장 가능, 퇴장한 참여자의 종목 처리
  - [X] 방장 퇴장 시 상장 완료 순서상 다음 참여자에게 위임
  - [X] 다음 참여자가 없으면 대기실 삭제
- 결정: 퇴장한 참여자의 종목은 삭제한다. 나간 플레이어 행도 삭제해 초대 코드로 다시 입장할 수 있다. 삭제된 대기실은 `DELETED` 상태로 남기고 초대 코드를 폐기한다.
- 비고: 퇴장은 구현됨. 종목 삭제는 market에 종목 삭제 서비스가 생기면 `LeagueLeaveUseCase`의 TODO에서 호출한다.

### LEA-07 방장은 리그 시작 전에 리그 이름 수정, 리그 삭제, 참여자 삭제를 할 수 있다
- Jira:
- 정책: [league.md#대기실](../../policies/v1/domain/league.md#대기실)
- 선행: LEA-05
- 완료 조건
  - [ ] 리그 이름 수정, 리그 삭제, 참여자 삭제는 방장만, 대기실 상태에서만 가능
- 결정 필요: 방장이 대기자(상장 전)도 삭제할 수 있는지

### LEA-08 생성 후 7일 안에 시작되지 않은 대기실은 초대 코드와 함께 만료된다
- Jira: ND-51
- 정책: [league.md#리그-생성-및-초대](../../policies/v1/domain/league.md#리그-생성-및-초대)
- 선행: LEA-01, GLB-03
- 완료 조건
  - [X] 대기실 생성 후 7일 내 미시작 시 대기실과 초대 코드 만료
  - [X] 만료된 리그는 동시 참여 수에서 제외
  - [X] 만료 시 초대 코드 폐기, 폐기된 코드는 다른 리그에 재발급 가능

## 진행

### LEA-09 방장은 참여자가 3명 이상이고 대기자가 없을 때 리그를 시작할 수 있다
- Jira: ND-56
- 정책: [league.md#리그-시작-및-운영](../../policies/v1/domain/league.md#리그-시작-및-운영)
- 선행: LEA-05
- 내용: 시작 조건 검증 후 참여자 명단 고정, `LeagueStarted` 이벤트 발행 → 자산 배분(AST-01) 완료 시 거래 개시
- 완료 조건
  - [X] 방장만 시작 가능, 참여자 3명 이상, 대기자 0명
  - [X] 자산 배분 완료 전에는 거래 불가 상태
  - [X] 시작 이후 리그 퇴장 불가
  - [X] 리그 시작 시 초대 코드 폐기
- 비고: 퇴장 불가는 대기실 퇴장(LEA-06) 구현 시 시작된 리그면 거절하도록 함께 처리한다.

### LEA-10 참여자는 리그 종료 시각과 현재 몇 거래일차인지 알 수 있다
- Jira:
- 정책: [league.md#리그-시작-및-운영](../../policies/v1/domain/league.md#리그-시작-및-운영), [market.md#시장](../../policies/v1/domain/market.md#시장)
- 선행: GLB-03
- 완료 조건
  - [ ] 종료 시각 = 시작 KST 날짜 + 7일, 09:00 KST
  - [ ] 00:00~09:00 시작 시 당일 09:00까지는 거래일 계산에서 제외, 사용자에게는 1일차로 표시
  - [ ] 특정 시각의 거래일 번호 계산 (09:00 이상 ~ 다음 날 09:00 미만)
  - [ ] 경계 시각(08:59:59, 09:00:00) 테스트

### LEA-11 진행 중인 리그는 매일 09:00 KST에 다음 거래일로 전환된다
- Jira:

  - [ ] 구독: MKT-06(종가 확정·기준가 적용), ORD-09(미체결 만료)
  - [ ] 서버 재시작·중복 실행 시에도 한 번만 처리

### LEA-12 리그는 종료 시각에 자동으로 종료되고, 이후에는 결과 페이지만 열린다

## 결과

### LEA-13 리그가 종료되면 참여자의 최종 총자산과 순위가 산정된다
- Jira:
- 정책: [league.md#리그-결과](../../policies/v1/domain/league.md#리그-결과)
- 선행: LEA-12, MKT-07, AST-05
- 완료 조건
  - [ ] 최종 총자산 = 최종 현금 + Σ(보유 수량 × 종료 평가 가격), 원 미만 절사
  - [ ] 자사주 포함, 총자산 동일 시 공동 순위
  - [ ] 최종 손익 = 최종 총자산 - 1억 원, 최종 수익률 = 최종 손익 ÷ 1억 원 × 100
  - [ ] 종료 전 탈퇴자는 순위·결과에서 제외
  - [ ] 결과 스냅샷 저장 (참여자별 현금, 종목별 보유 수량·평가액, 총자산)
- 결정 필요: 최종 수익률 반올림 규칙 (자산 조회와 같이 소수점 둘째 자리에서 반올림, 음수는 절댓값 기준인지)

### LEA-18 시스템은 거래일이 끝날 때마다 참여자별 총자산을 종가 기준으로 집계한다
- Jira:
- 정책: [league.md#리그-결과](../../policies/v1/domain/league.md#리그-결과)
- 선행: LEA-11, MKT-06, AST-08
- 완료 조건

  - [ ] 보유 주식은 해당 거래일 종가로 평가, 총자산 = 전체 현금 + 보유 주식 평가 금액

- 결정 필요: 저장 범위 (참여자별 총자산만인지, 종목별 보유 수량·평가액도인지)와 집계 결과의 사용처
